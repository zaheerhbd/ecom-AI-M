Phase 7: Microsoft Agent Framework as a second engine

The shop assistant can now run on Microsoft Agent Framework instead of our hand-written loop. One setting picks the engine. The API, the website and the database are unchanged, and both engines share the same tools, model, guardrails, memory, run records and evals.

  • What it is: Microsoft's ChatClientAgent now runs the "ask the AI → run tools → repeat" loop when Agent:Engine is AgentFramework. The default, Custom, is our own loop, exactly as before.
  • Only the loop is swapped. Everything around it (guardrails, the "is this your chat?" check, memory, the made-up-numbers check, run records, error messages) is the same code for both engines.
  • Works with every model we support: Gemini, OpenAI, Azure OpenAI and the free Fake model. Tested live with Gemini.
  • You can tell them apart on the Runs and Evals pages: framework runs show the model as gemini-3.5-flash (Agent Framework).

The main risk is cleared. Gemini needs its "thought signature" sent back after a tool call. Because the framework talks to the model through our model client, which already handles this, the live Gemini test worked first time.

How it works

The agent's work for one message has an outside part and an inside part. Phase 7 makes only the inside part replaceable:

  1. Input guardrails sharedLength limit, prompt-injection check, personal data masked.
  2. Load memory and check the chat belongs to you sharedSame memory store for both engines, so a chat could even change engine between messages.
  3. The loop swappableCustom: AgentRunner's own loop. AgentFramework: Microsoft's ChatClientAgent + FunctionInvokingChatClient, calling our model through LlmChatClient and our tools through ShopToolFunction.
  4. Output guardrails and the made-up-numbers check sharedSecret-leak check, personal data masked, prices and stock checked against tool data.
  5. Save memory (old tool results shrunk) and the run record sharedSame JSON answer, same Runs page, same Evals page.

The four new pieces

LlmChatClient

Shows our model client to the framework as Microsoft's IChatClient. It records each AI call as a step (tokens, time), enforces the token budget and the tool-call limit, and keeps the same trace spans and metrics.

Agent.Framework/LlmChatClient.cs

ShopToolFunction

Shows each of our 7 tools to the framework as an AIFunction. It runs them through our ToolRegistry, so the sign-in rule, the 10-second timeout and repeat detection still apply.

Agent.Framework/ShopToolFunction.cs

MessageMapper

Translates chat messages between our format and Microsoft's, keeping the exact tool arguments and Gemini's extra data on the way round.

Agent.Framework/MessageMapper.cs

FrameworkAgentLoop

Builds the framework agent for one message, runs it, and adds the new messages to our history. It also closes any tool request the framework left unanswered.

Agent.Framework/FrameworkAgentLoop.cs

How to switch engines

// appsettings (local)
"Agent": { "Engine": "AgentFramework" }      // or "Custom" (the default)

# Azure Container App (production) — environment variable
Agent__Engine=AgentFramework
  • No rebuild is needed: both engines are always in the app. A restart picks up the setting.
  • A typo (e.g. "Magic") stops the app at startup with a clear message, rather than failing on the first chat.
  • The model provider setting (Agent:Llm:Provider) is the same for both engines.
  • Production still uses Custom until you set the variable on the Container App.

What was added (NuGet)

One package, Microsoft.Agents.AI 1.28.0, only in the new Agent.Framework project. The Agent project (your hand-written engine) still has zero NuGet packages. With its dependencies, the app gets 11 new DLLs (about 3.9 MB):

DLLWhy
Microsoft.Agents.AI, Microsoft.Agents.AI.AbstractionsThe framework: ChatClientAgent, sessions, responses
Microsoft.Extensions.AI, Microsoft.Extensions.AI.AbstractionsIChatClient, AIFunction, the function-calling loop
Microsoft.Extensions.AI.Evaluation, Microsoft.Extensions.Compliance.Abstractions, Microsoft.Extensions.VectorData.Abstractions, Microsoft.ML.Tokenizers, Google.Protobuf, System.Numerics.Tensors, System.Memory.DataCome along with the framework; we don't call them

Smaller than first planned. The plan used Microsoft.Agents.AI.OpenAI, which also brings the OpenAI SDK (15 DLLs, about 9.6 MB). Plugging the framework into our own model client made that unnecessary, and it is also what fixed the Gemini risk.
