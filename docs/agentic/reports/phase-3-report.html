Phase 3: the agent can now use the shop

The agent "brain" from Phase 1 is now connected to the shop through 7 read-only tools and a chat API. You can ask it about products, policies, delivery and (when signed in) your orders, and every answer is saved with each step it took.

How a question is answered

  1. The browser sends the messagePOST api/agent/chat with { "message": "...", "sessionId": "..." }. If a login token comes with it, the user's email is read from the token (never from the message).
  2. Rate limitMore than 10 messages in a minute from the same user (or the same IP when anonymous) → "429 Too many messages".
  3. Input guardrailsToo long? Looks like "ignore your instructions"? Blocked here, before any money is spent. Card numbers and emails are masked.
  4. The think → act loopThe model reads the system prompt and the tool list, then either calls a tool (e.g. search_products) or answers. Tool results go back to the model. At most 6 rounds.
  5. Output guardrailsThe answer is checked for leaked secrets and personal data.
  6. Saved and returnedThe run (question, answer, steps, tokens, cost, sources) is saved in the AgentRuns table and returned to the caller.

The 7 tools

A tool is a normal C# class the model is allowed to call. All of them only read data. They live in Infrastructure/AgentTools/.

Safety and limits

Who the user is

Always from the login token (JWT). The model can't choose whose orders to read.

AgentController.Chat · GetMyOrdersTool · GetOrderTool

Admin role (D4)

A real "Admin" role now exists. It is added to the login token. In production only admins see runs and evals; in development everyone does.

AgentServiceExtensions · TokenService · AppIdentityDbContextSeed

Rate limit (D2)

10 messages per minute per signed-in user; anonymous visitors are counted by IP address.

AgentServiceExtensions (built-in ASP.NET Core rate limiter)

30-day history (D3)

A background job deletes runs older than 30 days, once a day.

Infrastructure/Services/AgentRunCleanupService.cs

Who becomes Admin: the emails listed in Agent:AdminEmails get the role when the app runs with --migrate. The list is empty for now; you'll add your own email in production (Phase 6).

Problems found and fixed while testing

  • Signed-in user told to sign in. The model didn't know that having the order tools means the user is signed in. Fixed in the system prompt and the tool description.
  • Wasted tool call + talking about "tools". Anonymous "my orders" first called the delivery tool and mentioned "order tools". Fixed in the prompt; the eval case now passes.

How to try it yourself

  1. Docker Desktop on, then cd API; dotnet run.
  2. Open https://localhost:5001/swagger, find Agent → POST /api/agent/chat, "Try it out", body: { "message": "Show me navy hats under $30" }.
  3. To continue the same conversation, copy sessionId from the answer into the next request.
  4. To test orders: Account → POST /api/account/login with bob@test.com / Pa$$w0rd, copy the token, click Authorize and paste Bearer <token>.
  5. See history: GET /api/agent/runs and GET /api/agent/stats.

Changes from the plan

  • Request context filled in the controller, not a separate middleware: only one endpoint needs it, so this is simpler to read.
  • Azure search for policies is opt-in (Agent:Knowledge:UseAzureSearch, default false), so the laptop never touches the live index.
  • 51 eval cases instead of ~45.
  • No test order for bob yet. bob has 0 orders, so the order tools were tested with "no orders" and "not found". Creating one means seeding data: your call.
  • Pricing for gpt-5.4-mini: $0.75 / $4.50 per million input/output tokens (OpenAI list price, checked 2026-11-21), set as a code default.
  • Gemini added (2026-11-22), now the default. One setting switches provider: Agent:Llm:Provider = Gemini or OpenAI. Each keeps its own key and model (Gemini:ApiKey/Gemini:Model, OpenAI:ApiKey/OpenAI:ChatModel). Gemini's free tier costs $0, so the cost shown is $0. Testing found two things, both fixed: Google had retired gemini-2.5-flash (now gemini-3.5-flash), and Gemini needs its "thought signature" sent back with each tool result. Free-tier limits: a few requests per minute and a daily cap, and Google may use free-tier data, so production should use a paid plan or OpenAI.

Words used

Tool
A C# method the model may ask to run, e.g. a product search.
System prompt
The agent's job description, sent before every conversation (API/Agent/system-prompt.md).
Run
One question and its answer, with every step in between.
Eval
An automatic test of the agent's behaviour: a question plus what a good answer must do.
Guardrail
A safety check in plain code, before or after the model.
Rate limit
A cap on how many messages one user can send per minute.
JWT
The login token. It says who you are and (now) whether you are an Admin.
