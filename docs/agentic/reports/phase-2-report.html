The shop API now returns these four fields too (ProductToReturnDto), so the shop pages can show them later. The Angular pages don't use them yet.

A small trap we avoided: there is no "default value" for stock in the C# model. If there were, EF would treat a real 0 ("out of stock") as "not set" and quietly save the default instead. The migration sets 25 on old rows with a plain SQL UPDATE.

New tables for runs and evals

Phase 1 kept runs and eval results in memory, so they vanish when the app restarts. These tables are where they will be saved from Phase 3 on. EF maps the engine's own record classes directly, so the engine still knows nothing about databases.

TableOne row isUsed by
AgentRunsOne question and answer, with every step, guardrail check, tool and source, plus tokens, cost and timeThe Runs page and its timeline (Phase 4)
EvalRunsOne test run of the AI: progress, pass rate, flaky count, latency, costThe Evals page
EvalCaseResultsOne test case inside an eval run ("TC-004 passed 3/3")The Evals page detail. Deleted with its eval run

Lists (steps, checks, sources, tools) are stored as JSON in jsonb columns, so a whole run comes back from one row. That logic is in one small helper, Infrastructure/Data/Config/JsonColumn.cs.

The product generator

A small Node script makes the catalogue: node tools/seed-gen/generate.js. It needs no internet and no AI.

  • Same output every time. It uses a fixed random seed, so running it again gives a byte-for-byte identical file (checked).
  • The original 18 products and 6 brands are copied unchanged from tools/seed-gen/original-products.json and original-brands.json.
  • 1,000 new products, 250 per type. Names like "Frostline Storm Trail Glove"; 14 invented brand names (not real companies).
  • Prices by type (boards $120–650, boots $60–320, gloves $12–110, hats $9–60), 12 colours, materials per type, ratings 2.5–5.0 (mostly high), and 96 products out of stock so "in stock" filters matter.
  • Pictures: each product reuses one of the 18 existing images of its type (decision D8). The choice is in one function, pictureFor, so switching to one picture per colour later is a one-line change.
  • Descriptions come from templates (free), for example: "A white bamboo snowboard, with a rocker profile that floats in deep powder and a twin shape, so it rides the same both ways. Great for beginners finding their feet."

Seeding that is safe to repeat

Before, the seed only filled empty tables, so it could never add the new products to a database that already had 18. Now it is idempotent: you can run it any number of times.

  1. Brands and typesAdd each one whose name isn't in the table yet. Old ids stay; new ones get the next free number.
  2. ProductsLoad all existing names once, then add every product whose name is new. Brand and type are found by name, so the file doesn't depend on database ids. Saved in batches of 200.
  3. Delivery methodsUnchanged: only when the table is empty.
  4. NeverUpdates or deletes an existing row. Your original products and any orders are left exactly as they are.

This is also what makes the production rollout in Phase 6 safe: the cloud database already has products and real orders, and the seed only adds what's missing.

Glossary

Migration
A script EF writes that changes the database structure (new columns, new tables), applied once and remembered.
Seed
Starting data loaded into the database from the JSON files.
Idempotent
Safe to run again: the second run changes nothing.
Fixed random seed
A starting number for the random generator, so "random" data comes out the same every time.
jsonb
A Postgres column type that stores JSON, so a list can live inside one row.
Fingerprint (MD5)
A short code calculated from data. If any character changes, the code changes.
Policy document
A short piece of shop rules the AI can search and quote, instead of guessing.
